## Why

Telemetry CSV files generated by `ping_checker.py` are frequently transferred across machines or shared with team members and first-line support engineers without their accompanying `.meta.json` sidecar. When received standalone, third-party analysts and helpdesk engineers face several ambiguities:
1. `ISP_Direct_IP` and `Zscaler_IP` contain identical destination IPs (due to dual-path `-S` interface binding vs tunnel routing), which looks like an error rather than concurrent dual-path probing.
2. `OVH_*` (Overhead) metrics are easily mistaken for the cloud hosting provider OVHcloud, and delta-jitter resulting in momentary negative latency (e.g. `-2.4ms` due to Wi-Fi 802.11 Power Save Mode beacon intervals) looks like a measurement bug.
3. Target IP transitions (from rotation to prevent remote edge rate-limiting/anti-DDoS) appear unannounced without target alias or cycle labels.
4. Essential hardware, OS, Wi-Fi PHY (RSSI, Channel, Band), power state (AC/Battery, Low Power Mode), and VPN process context are absent from the CSV file itself.

To make CSV telemetry self-contained and universally understandable to both automated ingestion tools and first-line support staff without breaking standard CSV parsers, we need a self-describing CSV format with structured `#` metadata header comments and intuitive, unambiguous column definitions (Schema v4).

## What Changes

- **Embedded Metadata Header Comments (`#`)**: Prepend structured `#` comment lines containing full host, OS, CPU architecture, Wi-Fi physical layer state (RSSI, Noise, Channel, Band, SSID/BSSID), power state (AC vs Battery, Low Power Mode), VPN client status, probe methodology explanation, and target rotation rationale.
- **Clean Self-Describing Column Schema (v4)**:
  - **BREAKING**: Replace duplicate `ISP_Direct_IP` and `Zscaler_IP` with atomic `Target_IP`, `Target_Alias` (e.g. `Cloudflare-Primary`, `OpenDNS-Primary`), and `Target_Pool_Index`.
  - **BREAKING**: Rename `ISP_Direct_RTT_ms` to `Direct_ISP_RTT_ms` and `Zscaler_RTT_ms` to `Tunnel_RTT_ms` (or `Zscaler_Tun_RTT_ms`).
  - **BREAKING**: Rename `Direct_Verified` to `Direct_Route_Verified` and `Zscaler_Verified` to `Tunnel_Route_Verified`.
  - **BREAKING**: Rename `OVH_*` columns to `Overhead_Delta_p50_ms`, `Overhead_Delta_p95_ms`, `Overhead_Baseline_p50_ms`, `Overhead_Loss_Delta_pct`, `Overhead_Alert`, and `Overhead_Alert_Reason`.
- **Version Bump & Schema Tracking**:
  - Bump `__log_schema__` to `4` and `__version__` to `1.4.0`.
  - Include explicit schema and script versions in both the top `#` header comments and the `.meta.json` sidecar.
- **First-Line Support Readability**:
  - Add explanatory probe methodology and overhead formula notes directly in the header comments so support engineers understand how latency deltas and `-S` interface binding work at a glance.

## Capabilities

### Modified Capabilities
- `network-path-monitoring`: Update CSV logging schema requirements and header structure to include self-contained metadata comments and self-describing column names.
- `overhead-statistics`: Update column names for overhead latency and jitter statistics to use explicit `Overhead_*` naming instead of `OVH_*`.
- `script-version`: Bump schema version to 4 and script version to 1.4.0.

## Impact

- **Affected Code**: `ping_checker.py` (`CSV_COLUMNS`, `init_logfile()`, `_write_log_footer()`, sample logging row builders, environment snapshot discovery functions).
- **Test Suite**: Update test assertions in `tests/` to reflect Schema v4 column headers and `#` commented header lines.
- **Documentation & OpenSpec**: All specs, examples, and telemetry guidelines updated to Schema v4.
